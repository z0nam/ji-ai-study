LLM 위키는 원본 메모(`inbox/`)는 건드리지 않고 AI가 주제별 정리본(`notes/`)과 목차(`index.md`)를 계속 다듬게 하며, 일하는 방식은 규칙 파일(`AGENTS.md`, `skills/`)로 관리하는 세컨드 브레인 방식이다.

## 1. 왜 일반 채팅창이나 RAG(문서 업로드)와 다른가
- **지식의 복리 축적(Compounding)**: 채팅창이나 단순 RAG 서비스는 질문할 때마다 원본을 처음부터 뒤지고 대화가 끝나면 답변이 휘발된다. 반면 LLM 위키는 새 자료를 넣을 때마다 AI가 기존 정리본(`notes/`)과 연결하고, 좋은 답변도 `queries/`에 파일로 저장해 두므로 쓸수록 위키가 똑똑해진다.
- **불변 원본과 언제든 되돌리기**: 원본(`inbox/`)은 절대 고치지 않으므로 AI의 정리가 마음에 안 들면 언제든 원본으로 다시 정리하거나 Git 커밋으로 되돌릴 수 있다.
- **결과 대신 규칙을 고친다**: 답변이나 정리 방식이 아쉬우면 결과물만 고치는 대신 `skills/`의 규칙에 한 줄을 추가해 다음부터 계속 그렇게 일하게 만든다.

## 2. 우리 소모임 심플 버전 구조와 5대 스킬
11/20 실습에서 익힌 심플 버전 구조에 공동 활용을 위한 **업데이트 스킬**과 **개인 연습 공간(`내연습/`)**을 더했다.
- **폴더**: `inbox/`(불변 원본), `notes/`(정리본), `queries/`(저장한 답), `index.md`(목차), `우리 목적.md`(수집·정리 기준), `내연습/`(Git에서 제외되는 개인 실험 공간).
- **5대 스킬 (`skills/`)**:
  1. **업데이트 스킬 (`업데이트.md`)**: 원격 GitHub 저장소의 새 소모임 자료를 확인하고 내 로컬 변경사항을 보호하며 최신 상태로 맞춘 뒤 변경점을 3줄로 요약한다.
  2. **정리 스킬 (`정리.md`)**: `inbox/`의 새 메모를 읽고 계획을 먼저 보여준 뒤 `notes/`와 `index.md`를 갱신한다.
  3. **질문 스킬 (`질문.md`)**: `index.md`와 `notes/`를 읽고 근거 노트·원문 문장과 함께 답한다.
  4. **점검 스킬 (`점검.md`)**: 어긋나는 내용, 고아 노트, 빠진 개념, 다음 소모임 주제를 찾아낸다.
  5. **리서치 스킬 (`리서치.md`)**: 웹이나 내 문서(`kordoc`으로 HWP·PDF·엑셀, `markitdown`으로 워드·PPT 변환)를 조사해 `inbox/리서치/`에 출처와 원문 문장을 저장한다.

## 3. 소모임에서 공동으로 쓸 때 지킬 원칙
- **작성(원문) · 파생(AI 정리본) · 공개의 분리**:
  - 일반 구성원은 상시 `"업데이트해줘"`로 최신 위키를 받아 `"질문 스킬로 답해줘"`로 활용하고, 개인 연습은 `내연습/` 폴더에서 진행한다.
  - 새 노하우를 보탤 때는 기존 파일을 고치지 않고 `inbox/`에 새 파일만 추가해 충돌을 막는다.
  - `notes/`와 `index.md`를 갱신하는 `정리 스킬`은 소모임 시간에 다 같이 실행하거나 운영진이 갈무리한다.
- **공개 저장소 보안**: 개인정보·연락처·계좌·비밀번호·API 키·내부 행정증빙(영수증·정산)·대외비 연구과제 원문은 붙이기 전에 반드시 지운다.
