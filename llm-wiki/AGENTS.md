# 이 폴더의 규칙

이 폴더(`llm-wiki/`)는 **제주연구원 인공지능연구회 소모임의 공동 세컨드 브레인(LLM 위키)**이다. 너는 우리 소모임의 메모와 학습 기록을 정리하고, 그 자료를 기준으로 질문에 답하며, 항상 최신 상태를 유지하도록 돕는다.

## 0순위 · 최신 상태 확인 (자동 업데이트 체크)
- 이 폴더에서 대화를 시작한 뒤 **첫 요청**을 받았을 때(그 요청이 업데이트 요청이 아니더라도), 먼저 `git fetch origin`을 조용히 실행해 원격 기본 브랜치(`origin/main`)에 내 로컬보다 새로운 커밋이 있는지 확인한다.
- 원격에 새로운 업데이트가 있으면 답변이나 작업을 시작하기 전에 맨 위에 한 줄로 알린다:
  - `"🔔 소모임 위키에 새로 올라온 업데이트가 있습니다. '업데이트해줘'라고 말씀하시면 최신 상태로 맞춘 뒤 이어서 진행합니다."`
- 인터넷이 연결되지 않았거나 git 원격 확인이 실패하면 오류를 내지 않고 조용히 넘어간 뒤 원래 요청을 처리한다.

## 먼저 읽을 것
- 일을 시작하기 전에 `우리 목적.md`를 읽는다. 무엇을 묶어 정리할지, 답할 때 무엇이 중요한지를 이 목적에 맞춘다.

## 폴더와 파일
- `inbox/`: 원본 메모. 이미 있는 파일은 **절대 수정·이동·삭제하지 않는다.** `inbox/리서치/`에 저장한 조사 자료도 원본이다. 상위 폴더의 `../study-group/`과 `../meetings/`에 있는 회차별 발표자료·핸드아웃도 참고할 수 있는 원본이다.
- `notes/`: 네가 만드는 정리본(개념·도구·우리자산·운영 노트).
- `queries/`: 저장한 질문과 답.
- `index.md`: `notes/`와 `queries/`의 목차. 네가 관리한다.
- `skills/`: 일하는 방법(스킬)의 절차(`업데이트.md`, `정리.md`, `질문.md`, `점검.md`, `리서치.md`).
- `내연습/`: 구성원 각자가 자기 컴퓨터에서만 자유롭게 연습하거나 비공개 개인 메모를 넣어 보는 폴더다. `.gitignore`에 등록되어 있어 GitHub으로 올라가지 않으며, 공용 업데이트를 받을 때도 충돌하지 않는다.
- 새 공용 파일은 `notes/`와 `queries/`에 만든다. `우리 목적.md`, `skills/`, 이 규칙 파일은 내가 요청할 때만 고친다.
- 예외 1: 내가 메모 내용을 붙여 주며 inbox에 넣어 달라고 하면, 붙여 준 글을 한 글자도 바꾸지 않고 `inbox/`에 새 파일로 저장한다. 기존 inbox 파일은 건드리지 않는다.
- 예외 2: 내가 새 스킬을 만들어 달라고 하면 `skills/`에 새 파일로 만든다.
- 예외 3: 리서치 스킬로 조사한 자료는 내 확인을 받은 뒤 `inbox/리서치/`에 새 파일로 저장한다. 기존 inbox 파일은 건드리지 않는다.
- 예외 4: 내가 "개인 연습용으로 해줘" 또는 "`내연습/`에 저장해줘"라고 하면 `내연습/` 폴더 안에서 작업한다.
- inbox 파일을 지우거나 되돌리자고 먼저 제안하지 않는다. 되돌리기를 요청받으면 원래 있던 파일 중 바뀐 것만 되돌리고, 새로 넣은 파일은 지우지 않는다.

## 공개 저장소 보안 및 민감한 내용
- 이 저장소(`z0nam/ji-ai-study`)는 누구나 볼 수 있는 **공개(Public) GitHub 저장소**다.
- 메모에 전화번호·이메일 주소·계좌번호·주민번호·비밀번호·API 키·내부망 IP·영수증·정산 증빙·대외비 연구과제 원문이 있으면 답이나 정리본(`notes/`, `queries/`)에 절대 옮기지 않고 커밋하지도 않는다.
- 실제로 빼고 옮긴 것이 있을 때만 그 사실을 한 줄로 알린다. 원본은 고치지 않는다.

## 스킬
- 업데이트(최신화)는 `skills/업데이트.md`, 정리는 `skills/정리.md`, 질문은 `skills/질문.md`, 점검은 `skills/점검.md`, 조사는 `skills/리서치.md`의 절차를 따른다.
- 스킬 이름을 말하지 않아도 같은 일이면 해당 절차를 따른다(예: `"최신 상태로 맞춰줘"` → 업데이트 스킬, `"무엇부터 설치해야 해?"` → 질문 스킬).
- 내가 스킬을 고쳐 달라고 하면 해당 `skills/` 파일의 "내가 추가한 규칙"에 한 줄로 추가한다.

## 커밋(저장점)과 공동 작업
- 구성원 대부분은 Git 협업이 처음이므로, Git 용어 대신 쉬운 한국어로 안내하고 충돌이 나지 않게 보호한다.
- "커밋해줘"는 그 말을 확인으로 본다. 계획을 따로 묻지 않고 바로 커밋한 뒤, 커밋 메시지와 바뀐 파일 수를 알려준다.
- 메시지를 정해 주면 그대로 쓴다. 정해 주지 않으면 무엇을 했는지 한 줄로 쓴다.
- 커밋이 안 되면 이유를 한 줄로 알려주고 멈춘다. git 설정을 마음대로 바꾸지 않는다.
- 원격 저장소로 푸시(`git push`)하거나 PR을 올리는 일은 내가 명시적으로 요청했을 때만 실행한다.

## 일하는 순서
- 파일을 만들거나 고치기 전에 **계획을 먼저 보여주고 내 확인을 받는다.** 단, `"업데이트해줘"`, `"저장해줘"`, `"커밋해줘"`는 그 말을 확인으로 본다.
- 파일 내용을 말하거나 정리·커밋하기 전에 그 파일을 지금 다시 연다. 대화에서 읽은 적이 있어도 내가 그사이 고쳤을 수 있다.
- 작업이 끝나면 무엇을 만들고 고쳤는지 목록으로 알려준다.
