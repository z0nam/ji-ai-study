# 업데이트 스킬 (sync)

원격 GitHub 저장소(`origin/main`)에 새로 올라온 소모임 자료와 위키 노트가 있는지 확인하고, 충돌 없이 내 컴퓨터의 위키를 최신 상태로 맞춘다.
Git 협업에 익숙하지 않은 구성원이 에러 메시지에 막히지 않도록 에이전트가 모든 충돌 예방과 백업을 대신 처리한다.

## 순서
1. 현재 Git 상태(`git status --porcelain`)와 원격 변경사항(`git fetch origin`)을 확인한다.
2. 원격 기본 브랜치(`origin/main`)에 내 로컬보다 새로운 커밋이 있는지(`git rev-list HEAD..origin/main --count`), 그리고 내 컴퓨터에서 수정되거나 추가된 파일이 있는지 확인한다.
3. 상황별로 아래 규칙에 따라 안전하게 최신화한다. **"`업데이트해줘`", "`최신 상태로 맞춰줘`" 요청은 그 말을 확인으로 보고 바로 진행한다.**
   - **상황 A (내 컴퓨터에서 바뀐 공용 파일이 없고 원격에 새 업데이트만 있을 때)**:
     - 바로 `git pull --ff-only origin main`(또는 `git merge origin/main`)으로 최신 파일을 받는다.
   - **상황 B (내 컴퓨터에서 `notes/`, `index.md`, `inbox/` 등 공용 추적 파일을 수정해 놓아서 충돌 위험이 있을 때)**:
     - Git 에러가 나도록 그냥 `git pull`을 하지 않는다.
     - 먼저 `내연습/백업/YYYY-MM-DD_HHMM/` 폴더를 만들고, 내가 로컬에서 수정한 파일들의 사본을 그 안에 그대로 복사해 둔다.
     - 그다음 로컬 추적 파일의 변경사항을 원래대로 돌린 뒤(`git checkout -- .` 또는 `git stash push -m "auto-backup-before-sync"`), `git pull --ff-only origin main`으로 공식 최신 본을 깨끗하게 받는다.
     - 사용자에게 *"내 컴퓨터에서 수정하셨던 파일은 지워지지 않게 `내연습/백업/` 폴더에 안전하게 따로 보관해 두고, 소모임 공식 최신 위키로 맞췄습니다"*라고 친절하게 알린다.
   - **상황 C (이미 최신 상태일 때)**:
     - *"현재 소모임 위키가 이미 가장 최신 상태입니다."*라고 알리고 가장 최근 커밋 1~2개의 날짜와 제목을 보여준다.
4. 새로 받아온 업데이트가 있다면, 방금 들어온 커밋 로그(`git log ORIG_HEAD..HEAD --oneline`)와 바뀐 `notes/`·`inbox/` 파일 목록을 확인해 **"이번 업데이트로 새로 추가되거나 바뀐 소모임 내용"**을 쉬운 한국어 3줄 이내로 브리핑한다.

## 지킬 것
- `내연습/` 폴더 안의 파일은 구성원의 개인 공간이므로 절대 삭제하거나 덮어쓰지 않는다.
- 사용자가 로컬에 새로 만들어 둔 미추적 파일(untracked file)이 있을 때도 절대 삭제(`git clean -f` 등)하지 않는다. 만약 원격에서 새로 내려오는 파일과 이름이 겹치면 내 파일을 `내연습/백업/`으로 옮긴 뒤 업데이트한다.
- Git 전문 용어(rebase, detached HEAD, fast-forward 등)를 그대로 늘어놓지 말고, 구성원이 이해하기 쉬운 말로 결과만 깔끔하게 설명한다.
