# AI 에이전트 핵심 개념 핸드아웃
**CLI · 에이전트 · MCP · 스킬 · 플러그인, 비유 하나로 끝내기**

---

## 큰 그림: "AI 신입사원" 비유

우리 팀에 아주 똑똑한 **신입사원(= AI 에이전트)**이 들어왔다고 상상해보세요.
똑똑하지만 우리 회사 사정은 하나도 모릅니다. 이 신입을 일 잘하게 만들려면 뭐가 필요할까요?

| 필요한 것 | AI 세계의 이름 | 한 줄 정의 |
|---|---|---|
| 대화할 창구 | **CLI** | 신입과 이야기하는 터미널 창 |
| 사내 시스템 출입증 | **MCP** | 그룹웨어·슬랙·한글문서 등 외부 시스템에 접속하는 표준 연결 규격 |
| 업무 매뉴얼 | **스킬(Skill)** | "이 일은 이렇게 처리해"라고 적어둔 작업 절차서 |
| 매뉴얼+출입증 세트 상자 | **플러그인(Plugin)** | 스킬·명령어·MCP 연결을 한 번에 설치하는 꾸러미 |
| 팀 규칙 게시판 | **CLAUDE.md / AGENTS.md** | 매번 말 안 해도 항상 지키는 우리 팀 기본 규칙 |

이 다섯 개가 오늘 배울 개념의 전부입니다. 하나씩 봅시다.

## 1. CLI — 신입사원과 대화하는 창구

**정의**: Command Line Interface. 마우스로 클릭하는 화면 대신, 글자를 입력해서 컴퓨터와 대화하는 검은 창(터미널).

- 채팅창과 뭐가 다른가? **겉모습은 거의 같습니다.** 한국어로 문장을 치면 답이 옵니다.
- 결정적 차이: 채팅창의 AI는 우리 컴퓨터 밖에 있지만, CLI의 AI는 **지금 내가 있는 폴더 안에서** 일합니다. 파일을 읽고, 만들고, 프로그램을 실행할 수 있습니다.
- 예: 터미널에서 `claude`라고 치면 Claude Code가, `codex`라고 치면 Codex가 켜지고, 그 다음부터는 그냥 한국어로 말하면 됩니다.

```
> 이 폴더에 있는 hwp 파일 3개를 전부 pdf로 바꿔줘
```
채팅창이라면 "파일을 업로드해주세요"라고 하겠지만, CLI 에이전트는 폴더를 뒤져서 직접 변환합니다.

---

## 2. 에이전트 — 답만 하는 AI가 아니라 일하는 AI

**정의**: 목표를 주면 스스로 계획을 세우고, 도구(파일 읽기, 명령 실행, 브라우저 조작 등)를 써가며, 결과를 확인하고, 틀리면 다시 시도하는 AI.

- 채팅 AI: "pdf 변환은 이런 코드를 쓰시면 됩니다" (말로 끝)
- 에이전트: 코드를 만들고 → 실행하고 → 에러 나면 고치고 → 변환된 pdf를 폴더에 놓고 → "3개 완료했습니다" (일로 끝)
- 오늘 시연한 사례1(그룹웨어 일정 등록 → 슬랙 공지)이 전형적인 에이전트 작업입니다. 사람은 문장 하나만 말했고, 나머지는 에이전트가 알아서 했습니다.

## 3. MCP — 외부 시스템 출입증 (가장 중요한 개념)

**정의**: Model Context Protocol. AI가 외부 프로그램·서비스와 연결되는 **표준 규격**. "AI용 USB-C 단자"라고 생각하면 정확합니다.

USB-C 규격 덕분에 어떤 회사 충전기든 어떤 폰에나 꽂히듯, MCP 규격 덕분에 **하나의 MCP 서버를 Claude Code에도, Codex에도, Antigravity에도 똑같이 꽂아 쓸 수 있습니다.**

### 왜 필요한가
AI는 원래 그룹웨어, 슬랙, 한글(hwp) 문서 형식을 모릅니다. MCP 서버는 "슬랙에 메시지 보내는 법", "hwpx 파일 여는 법"을 AI가 쓸 수 있는 **도구 버튼** 형태로 제공합니다. 꽂는 순간 AI에게 새 능력이 생깁니다.

### 이미 만들어져 있는 것 (가져다 꽂기만 하면 됨)
- **Slack MCP** — 채널 읽기/쓰기, 파일 공유 (사례2에서 슬랙에 올린 것)
- **Google Drive / Gmail / Calendar MCP** — 문서 검색, 메일, 일정
- **GitHub MCP** — 코드 저장소 관리
- **Playwright/브라우저 MCP** — 웹사이트 접속, 클릭, 입력 (사례1의 그룹웨어 조작)
- 수천 개가 공개돼 있고, 계속 늘어납니다

### 우리가 직접 만든 것 (로컬 MCP — 이 채널에서 이미 쓰고 있는 것들)
- **hwpx-mcp** — 이중화 님이 설치 가이드 공유한 그것. AI가 hwpx 문서를 읽고 쓰게 해줌
- **ji-gw-ai** — 우리 기관 그룹웨어 접속용. 일정 등록, 결재 확인 등을 AI가 직접 수행

### 꽂는 방법 (도구별 명령 한 줄)
```bash
# Claude Code
claude mcp add 이름 -- 실행명령        # 예: claude mcp add hwpx -- npx hwpx-mcp

# Codex
codex mcp add 이름 --command "실행명령"

# Antigravity
우측 상단 Agent 옆 [...] → MCP Servers 메뉴에서 추가 (클릭으로 설정)
```
한 번 꽂아두면 그 뒤로는 그냥 말만 하면 됩니다: "그룹웨어에서 내일 일정 확인해줘"

## 4. 스킬 — 업무 매뉴얼 폴더

**정의**: 특정 작업의 절차·요령·주의사항을 적은 **매뉴얼 파일(SKILL.md)이 든 폴더**. AI가 관련 작업을 만나면 이 매뉴얼을 꺼내 읽고 그대로 따라 합니다.

MCP와의 차이를 비유로:
- **MCP = 출입증** (그룹웨어에 "들어갈 수 있게" 해줌)
- **스킬 = 매뉴얼** (들어가서 "우리 방식대로 일하게" 해줌)

### 예: mail-skill (우리 기관용 메일 작성 스킬이라면)
```
mail-skill/
└── SKILL.md
```
SKILL.md 내용 예시:
```markdown
---
name: mail-skill
description: 기관 공식 메일 초안 작성 시 사용
---
# 기관 메일 작성 규칙
- 첫 줄 인사: "안녕하십니까, ○○센터 ○○○입니다."
- 존댓말, 두괄식으로 용건 먼저
- 마지막에 서명 블록 포함: (이름/부서/내선)
- 외부 발송 메일은 기관 명칭을 풀네임으로 표기
```
이 폴더를 스킬 위치(예: Claude Code는 `~/.claude/skills/`)에 넣어두면, "회의 일정 조율 메일 초안 써줘"라고 할 때 AI가 알아서 이 규칙대로 씁니다. **매번 규칙을 다시 설명할 필요가 없어지는 것**이 핵심입니다.

### 예: calendar-worklog (일정 → 업무일지 스킬이라면)
"이번 주 업무일지 써줘" 한 마디에 → (ji-gw-ai MCP로 그룹웨어 일정을 읽고) → calendar-worklog 스킬의 양식·문체 규칙대로 → 업무일지 초안 완성. **MCP(출입증) + 스킬(매뉴얼)이 조합되는 전형적인 패턴**입니다.

### 예: hwp-agent (hwp 문서 처리라면)
hwpx-mcp(출입증)로 문서를 열고, hwp 스킬(매뉴얼: 서식 규칙, 표 처리 요령, "1줄 단어 중복 문제는 이렇게 후처리" 같은 노하우)대로 작업. 지난 6월에 공유된 "hwpx 문서 작성 md 파일"이 사실상 스킬의 원형입니다.

### 스킬 만들기는 코딩이 아닙니다
한국어로 매뉴얼을 쓰는 일입니다. 심지어 에이전트에게 "내가 방금 한 이 작업 과정을 스킬로 저장해줘"라고 시켜도 됩니다.

## 5. 플러그인 — 세트 상자

**정의**: 스킬 + 단축 명령어 + MCP 연결 설정을 **하나로 묶어 배포하는 꾸러미**. "신입사원 온보딩 키트"입니다.

- 예: 누군가 "제주연구원 업무 플러그인"을 만들면 → 그 안에 ji-gw-ai(MCP) + mail-skill + calendar-worklog + hwp-agent가 전부 들어있고 → 동료는 설치 한 번으로 전부 갖춤
- Claude Code 설치: `/plugin` 명령으로 마켓플레이스 등록 → 설치
- Antigravity는 VS Code 기반이라 **확장 프로그램(Extensions)** + Rules/Workflows가 비슷한 역할
- **소모임 관점에서 중요한 이유**: 한 명이 잘 만들면 → 플러그인으로 묶어서 → 채널에 공유 → 전원이 즉시 같은 능력을 갖게 됨. hwp2pdf 봇 공유의 확장판.

## 6. CLAUDE.md / AGENTS.md — 팀 규칙 게시판

**정의**: 프로젝트 폴더 맨 위에 두는 텍스트 파일. AI가 **대화 시작할 때마다 자동으로 읽는** 상시 지침.

```markdown
# AGENTS.md 예시
- 모든 답변과 주석은 한국어로
- 문서 날짜 표기는 YYYY-MM-DD
- 그룹웨어 관련 작업은 반드시 실행 전에 나에게 확인받을 것
```
- Claude Code는 `CLAUDE.md`, Codex와 Antigravity는 `AGENTS.md`를 읽습니다 (내용은 사실상 같음)
- 스킬과의 차이: 스킬은 "특정 작업의 매뉴얼"(필요할 때만 꺼냄), 이 파일은 "항상 적용되는 기본 규칙"

## 한 장 요약: 전부 조합하면 이렇게 됩니다

> **나**: "이번 주 업무일지 작성해서 그룹웨어에 올리고, 요약을 소모임 채널에 공유해줘"
>
> **에이전트**(CLI에서 대화) →
> ① AGENTS.md의 기본 규칙 확인 →
> ② **ji-gw-ai(MCP)**로 그룹웨어 접속해 이번 주 일정 조회 →
> ③ **calendar-worklog(스킬)** 매뉴얼대로 업무일지 작성 →
> ④ **hwp-agent + hwpx-mcp**로 기관 양식 hwpx 파일 생성 →
> ⑤ 그룹웨어 등록 →
> ⑥ **Slack MCP**로 소모임 채널에 요약 공유 →
> "완료했습니다. 확인해주세요."

문장 하나 = 출입증(MCP) 여러 장 + 매뉴얼(스킬) 여러 권의 합주. 이게 에이전트 활용의 최종 그림입니다.
